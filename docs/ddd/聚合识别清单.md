## 一、识别范围与口径

- 聚合以一致性边界判定：外部只能通过聚合根修改聚合内部，聚合内部在同一事务内保持一致。
- 本项目采用模块化单体 + 六边形分层：跨上下文只经 `*-api` 发布语言或集成事件通信（ADR-001）；领域与持久化分离（ADR-008），持久化实体与计数器不属于聚合边界。
- 清单覆盖四个限界上下文：Identity、Q&A、Reputation、Discovery。

## 二、聚合总览

| # | 聚合 | 根实体 | 限界上下文 | 关键不变式 |
|---|---|---|---|---|
| 1 | `User` | User | Identity | username 唯一且不对外展示；displayName 全局唯一；verified 仅学院管理员可置位 |
| 2 | `Course` | Course（成员为实体 `CourseMember`） | Identity | 同一课程代码在同一学期唯一；用户在同一课程中角色唯一 |
| 3 | `Question` | Question | Q&A | 最多一个被采纳答案且不可逆；已删除后只读；提问者只能删无回答的问题 |
| 4 | `Answer` | Answer | Q&A | 必须属于未删除的问题；采纳状态由 Question 单一持有；被采纳后作者不可删 |
| 5 | `Vote` | Vote | Q&A | 一人一内容一票；值 ±1；撤销即删除；不能投自己的内容 |
| 6 | `Comment` | Comment | Q&A | 必须挂在未删除的问题/回答上；回复只允许一层 |
| 7 | `ReputationAccount` | ReputationAccount | Reputation | reputation 恒等于账本流水之和；余额只能由流水改变 |
| 8 | `Bounty` | Bounty | Reputation | OPEN→AWARDED/EXPIRED，终态不可变；积分 10–500、期限 1–14 天；发起人不得自赢 |
| 9 | `Notification` | Notification | Discovery | (sourceEventId, recipientId) 唯一；仅接收者可标记已读 |
| 10 | `SearchDocument` / `SearchIndex` | — | Discovery | 只读投影，随事件重建，不反向影响业务 |

> 值对象不作为聚合单列，在各聚合详解中列出：Identity 的 `CourseRole`；Q&A 的 `Title`/`MarkdownBody`/`Tags`/`TagName`/`TargetType`；Reputation 的 `LedgerEntry`；Discovery 的 `SearchQuery`/`SearchDocument`/`SearchHit`。

## 三、逐聚合详解

### 3.1 Identity 上下文

#### 1. `User`（用户聚合根）

| 项 | 内容 |
|---|---|
| 根实体 | `User` |
| 内部属性 | `username`（学号/工号）、`displayName`、`verified`、`role`、`status` |
| 关键不变式 | ① `username` 是登录凭据，属个人信息，不对外展示；② `displayName` 全局唯一（用于 `@提及`）；③ `verified`（校园身份认证）只能由学院管理员置位 |
| 一致性边界 | 单用户。注册、认证、改角色、停用各自独立事务 |
| 代码位置 | `co-identity/co-identity-domain/.../domain/User.java` |

#### 2. `Course` / `CourseMember`（课程聚合根）

| 项 | 内容 |
|---|---|
| 根实体 | `Course`；`CourseMember` 为聚合内实体 |
| 聚合归属 | `Course` 为独立聚合根；`CourseMember` 归属 `Course` 聚合，而非 `User` 聚合 |
| 内部属性 | `courseId`、学期、`CourseMember`（userId + `CourseRole`） |
| 关键不变式 | ① 同一课程代码在同一学期唯一；② 同一用户在同一课程中只有一种 `CourseRole`（STUDENT/TEACHER/TA）；③ 课程教师在该课程内的角色不可被降级 |
| 一致性边界 | 单课程。成员增减与课程信息修改同事务 |
| 代码位置 | `co-identity/co-identity-domain/.../domain/Course.java`、`CourseMember.java`、`CourseRole.java` |

> `PasswordPolicy`（8–64 位、同时含字母与数字）与 `PasswordHasher`（BCrypt 端口）为领域策略/端口，不属于聚合。

### 3.2 Q&A 问答上下文

#### 3. `Question`（问题聚合根）

| 项 | 内容 |
|---|---|
| 根实体 | `Question` |
| 值对象 | `Title`（10–150 字符）、`MarkdownBody`、`Tags`（去重后 1–5 个 `TagName`，每个 1–30 字符、统一小写） |
| 关键不变式 | ① 最多一个被采纳的答案，且采纳后不可更改（重复采纳 → `ConflictException` QA-2002）；② 只有提问者或课程管理者（教师/助教/管理员）可以采纳（否则 `ForbiddenException` QA-3001），且被采纳的回答必须属于本题、未删除（否则 422）；③ 已删除的问题不能再被回答、编辑或采纳；④ 提问者只能删除尚无回答的问题，课程管理者可删除任意问题；⑤ 每个问题必须带 1–5 个标签 |
| 反规范化字段 | `score`/`answerCount`/`viewCount` 为只读计数器，不由聚合回写，由仓储以原子 SQL 维护（ADR-008） |
| 一致性边界 | 单问题。采纳是 Question 与 Answer 之间的跨聚合操作，由应用服务编排：Question 改 `acceptedAnswerId` → 发布 `AnswerAcceptedEvent` → Reputation 异步响应 |
| 代码位置 | `co-qa/co-qa-domain/.../domain/Question.java` |

#### 4. `Answer`（回答聚合根）

| 项 | 内容 |
|---|---|
| 根实体 | `Answer` |
| 内部属性 | `questionId`、`authorId`、`body`、`score`（只读）、`endorsedBy`（教师认证人）、`deletedAt` |
| 关键不变式 | ① 必须属于一个未删除的问题（`submit` 时校验 Question）；② 「是否被采纳」不在本聚合存储，由 `Question.acceptedAnswerId` 单一事实来源持有；③ 教师认证（`endorse`）只能由课程管理者执行，且每个回答只能认证一次（重复 → `ConflictException` QA-2003）；④ 被采纳的回答不能由回答者本人删除，课程管理者可删除；非作者不得编辑或删除他人内容（`ForbiddenException` QA-3002/3003/3004） |
| 一致性边界 | 单回答。独立于 Question 聚合以降低并发冲突 |
| 与 Question 的关系 | 通过 `questionId` 引用，不持有 Question 对象引用 |
| 代码位置 | `co-qa/co-qa-domain/.../domain/Answer.java` |

#### 5. `Vote`（投票聚合）

| 项 | 内容 |
|---|---|
| 根实体 | `Vote` |
| 内部属性 | `voterId`、`targetType`（QUESTION/ANSWER）、`targetId`、`value`、`updatedAt` |
| 关键不变式 | ① 同一用户对同一内容仅一票（数据库唯一约束兜底）；② 值为 `+1` 或 `-1`（`checkValue`），撤销即删除（不做 0 值行）；③ 改投（`change`）返回原值供声誉冲正；④ 不能给自己的内容投票（`BusinessRuleException` QA-1015） |
| 一致性边界 | 单张票。投票不直接改内容分数，分数由计数器原子维护 |
| 代码位置 | `co-qa/co-qa-domain/.../domain/Vote.java` |

#### 6. `Comment`（评论聚合）

| 项 | 内容 |
|---|---|
| 根实体 | `Comment` |
| 内部属性 | `targetType`、`targetId`、`questionId`、`authorId`、`parentId`（二级回复）、`body`、`createdAt` |
| 关键不变式 | ① 必须挂在未删除的问题或回答上；② 回复只允许一层（`parentId` 不为空时不得再回复，QA-1016）；③ 回复必须与父评论在同一目标上（QA-1017）；④ 评论长度 2–600 字符（QA-1003）；⑤ 评论不参与投票与声誉（v1.0 范围） |
| 一致性边界 | 单条评论 |
| 代码位置 | `co-qa/co-qa-domain/.../domain/Comment.java` |

> Q&A 其余构造块：`Title`/`MarkdownBody`/`Tags`/`TagName`/`TargetType` 为值对象；`QuestionRepository`/`AnswerRepository`/`VoteRepository`/`CommentRepository` 与 `TagRepository`（热门标签计数）为仓储接口，实现均在基础设施层。

### 3.3 Reputation 声誉上下文

#### 7. `ReputationAccount`（声誉账户聚合根）

| 项 | 内容 |
|---|---|
| 根实体 | `ReputationAccount` |
| 内部属性 | `reputation`、`availablePoints`（可用悬赏积分）、`frozenPoints`（冻结悬赏积分）、`version` |
| 关键不变式 | ① `reputation` 恒等于该用户所有账本流水 delta 之和（由对账任务 FF-8 验证）；② 余额只能由账本流水改变，不可直接改写；③ 悬赏积分 = 可用 + 冻结，冻结部分在结算或到期时释放；④ 规则调整时只追加冲正账目，不改写历史 |
| 一致性边界 | 单账户。账目追加与余额更新同事务 |
| 代码位置 | `co-reputation/co-reputation-domain/.../domain/ReputationAccount.java` |

#### 8. `Bounty`（悬赏聚合根，状态机）

| 项 | 内容 |
|---|---|
| 根实体 | `Bounty` |
| 状态机 | `OPEN →（问题采纳）→ AWARDED`；`OPEN →（到期）→ EXPIRED`；终态不可再变 |
| 内部属性 | `questionId`、`sponsorId`、`points`（10–500）、`expiresAt`（1–14 天）、`winnerId`、`answerId`、`closedAt` |
| 关键不变式 | ① 发起人须为课程管理者（教师/助教/管理员，REP-3001）；② 问题不能已删除或已采纳（REP-1001/1005）；③ 发起人不能赢得自己的悬赏（REP-1006）；④ 开启时从发起人账户冻结积分，结算时转出（`spendFrozen`）、到期时退回（`refundFrozen`），不可超额支付 |
| 一致性边界 | 单笔悬赏。冻结/发放/退回涉及与 `ReputationAccount` 的协作，由应用服务编排 |
| 代码位置 | `co-reputation/co-reputation-domain/.../domain/Bounty.java` |

> Reputation 其余构造块：`LedgerEntry`（只追加流水值对象，幂等键 `(eventId, userId, reason)`）；`ReputationRulebook`（策略：采纳 +15 / 被赞 +10 / 被踩 −2，差值计分、每日上限 200、开户积分）；`BadgePolicy`（按采纳数与声誉阈值授予徽章）；`AcademicTerm`（Asia/Shanghai 学期/周/月键，领域服务）。

### 3.4 Discovery 内容发现上下文

#### 9. `Notification`（通知聚合根，读模型）

| 项 | 内容 |
|---|---|

| 内部属性 | `recipientId`、`type`、`title`、`link`、`sourceEventId`、`read`、`createdAt` |

#### 10. `SearchDocument` / `SearchIndex`（读模型）

| 项 | 内容 |
|---|---|
| 性质 | 读模型（Read Model）：`SearchDocument` 是搜索投影的写模型，`SearchHit` 是读结果 |
| 关键不变式 | ① 只读投影，与 Q&A 的问题聚合是两个模型，只关心「如何被找到」；② 可重放重建（事件重放后结果一致）；③ `SearchIndex` 由事件投影器维护 |

| 代码位置 | `co-discovery/co-discovery-domain/.../domain/search/`、`.../domain/notification/` |

## 四、跨上下文聚合关系与事件

| 上游 | 下游 | 关系模式 | 集成方式 |
|---|---|---|---|
| Identity.User | Q&A / Reputation / Discovery | 开放主机服务 + 发布语言（OHS/PL） | 同步 `IdentityApi`（只给 UserSummary）+ 异步 `UserRegisteredEvent` |
| Q&A.Question/Answer/Vote | Reputation.ReputationAccount | 客户/供应商（Customer/Supplier） | 异步 `Answer*/VoteCastEvent`；同步 `QaQueryApi.findQuestion` |
| Q&A.Question/Answer/Vote/Comment | Discovery.SearchDocument / Notification | 遵奉者（Conformist） | 异步 `Question*/Answer*/Vote/Comment/ContentDeleted` 事件折叠为投影 |
| Reputation.Bounty/Badge | Discovery.Notification | 遵奉者（Conformist） | 异步 `Bounty*/BadgeAwardedEvent` |
| 全部上下文 | — | 共享内核（Shared Kernel） | Maven 依赖 `co-shared-kernel` |

> 跨上下文一致性走事务性发件箱（ADR-002），事件先落 `outbox_event` 由中继投递；消费端以幂等键去重（`LedgerEntry` 的 `(eventId,userId,reason)`、`Notification` 的 `(sourceEventId,recipientId)`、`ProcessedEventStore`）。

## 五、设计取舍说明

1. `Answer` 独立于 `Question`，而非作为 `Question` 的内部实体：回答是高频并发写操作，若作为问题聚合的内部集合，每次回答都会锁住整个问题聚合，事务粒度和冲突率不合理。代价是「采纳」成为跨聚合操作，需应用服务编排 + 事件驱动（ADR-002）。
2. 「是否被采纳」只存在于 `Question` 一处（单一事实来源）：避免双写不一致；`Answer` 不存 `accepted` 字段，查询采纳状态以 `Question.acceptedAnswerId` 为准。
3. 计数器（`score` / `answerCount` / `viewCount`）不由聚合维护：ADR-008 规定由原子 SQL `UPDATE` 维护，避免读-改-写覆盖并发增量。
4. 声誉账目化：`reputation` = 账本流水之和，任何变动留痕、可冲正、可审计（FF-8 对账验证），规则调整时只追加冲正账目，不改写历史。
5. `Vote` 独立成聚合：「一人一票」唯一约束落到数据库唯一索引，聚合层只管 ±1 与改投（返回原值供冲正）。
6. Discovery 只有读模型：`SearchDocument` / `Notification` 是事件投影，不接受业务命令直接修改，天然最终一致。
