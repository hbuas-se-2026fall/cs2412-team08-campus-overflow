## 四、Sprint 目标回顾（30 秒口播稿）

> 本 Sprint 我们承诺五件事：把问答链路上的投票、评论、采纳、热门标签从骨架做成可用用例，把问答行为通过领域事件转化成声誉、徽章、悬赏和排行榜。
> 兑现情况：投票支持点赞、踩、取消与改投，同一用户重复点赞不重复计分；采纳只有提问者或课程教师/助教能操作，重复采纳会被拒绝；评论支持一层回复；热门标签按关联问题数排序。
> 声誉侧，采纳后回答者声誉 +15 并发放「初露锋芒」徽章，被赞 +10、被踩 −2、赞改踩 −12，同一自然日（Asia/Shanghai）因被投票获得的正向声誉最多 200 分；教师初始悬赏积分 1000、学生 0；悬赏支持发起、结算和到期退款；排行榜支持周、月、学期、总榜；对账接口返回不一致明细，当前为空。
> 关键一点是链路走的是领域事件：问答模块只负责发布采纳与投票事件，声誉模块在自己的事务里监听记账，两个模块之间没有直接调用。

## 六、已修复的跨模块协作缺陷

| 现象 | 根因 | 修复（PR / commit） |
| --- | --- | --- |
| 回答被删除后，所属问题的回答数不回落 | 问答模块发布 `ContentDeletedEvent`，发现模块的投影只处理了 `QUESTION` 分支，`ANSWER` 分支缺失，索引里的 `answer_count` 不调整 | #93 `ef06972`：补 `ANSWER` 分支并按 `GREATEST(answer_count - 1, 0)` 回落，同时新增采纳与重复投递测试 |
| 搜索结果列表显示「0 浏览」 | 后端 `SearchResultView` 不含 `viewCount`，前端 `SearchResult` 继承 `QuestionSummary` 强依赖该字段，缺失时被渲染成 0 | #96 `e6aae70`：`SearchResult` 拆为独立接口，`viewCount` 改为可选，只在存在时渲染 |
| 评论里 `@昵称` 的高亮范围与后端识别不一致 | 前端正则 `@[\w\u4e00-\u9fa5.-]+` 会把尾随标点吞进高亮，且单字符昵称也会命中 | #96 `e6aae70`：改为 `/@[\w\u4e00-\u9fa5]{2,20}/g`，与后端 2–20 字符口径对齐 |

## 八、风险与兜底

| 风险 | 现场表现 | 兜底动作 |
| --- | --- | --- |
| 跑的镜像不是最新 main | 搜索、通知、单条已读等新功能返回 501 | 用最新 main 重新构建镜像（`docker compose -f deploy/docker-compose.yml build`）后重启 |
| 悬赏结算演示顺序搞错 | 采纳时没有发放悬赏 | 采纳前先看 q2 的悬赏状态，确认仍是 OPEN 再操作 |

| 网络或服务异常 | 页面打不开 | 切成本地已跑通的录屏片段或截图，不占用提问时间 |
| 现场账号登录失效 | 401 | 提前准备已登录会话的浏览器标签页，不现场登 |
