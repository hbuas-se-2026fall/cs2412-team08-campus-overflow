流水线侧有三处缺口，缺任一处都产不出回归对象：

| 缺口 | 现状 | 后果 |
| --- | --- | --- |
| 镜像推送 | `images` 作业只有 `docker build`，无 registry 登录、无 `docker push` | 镜像留在 runner 上随运行销毁，服务器取不到 |
| 部署作业 | 无 deploy job，无 ssh 或 registry 拉取步骤 | 没有自动部署路径，只能人工搬运 |
| 服务器接入 | 无主机地址、账号、密钥类 Secrets | 即便补上 deploy job 也连不上目标机 |

补一条容易误读的：`images` 作业带 `if: github.event_name == 'push'`，所以 PR 上显示 skipped 是正常的，不代表镜像没构建过；push 到 main 时会构建，但构建完仍然不推送。

## 四、本地环境限制

本机无可用 Docker，也没有可用的 WSL 备用路径（CBS 修复失败，报 0x800703F1）。所以「本地起 compose 先自测」这条退路同样不成立：`docker compose up` 无法执行，E-03 的健康检查在本地也验不了。这条写在这里，是为了在评审会上被问「为什么不先在本地跑一遍」时有据可答。

## 五、解除阻塞需要什么

四项，按依赖顺序，前两项是外部资源，后两项是流水线改造：

| 序 | 事项 | 提供方 | 需要拿到的具体内容 |
| --- | --- | --- | --- |
| 1 | 测试服务器子域名 | 王钰滢、张嘉雨对接课程方 | 完整域名，且 `nslookup` 能返回解析 |
| 2 | 服务器 SSH 接入 | 同上 | 主机地址、端口、账号、密钥或密码方式 |
| 3 | 镜像分发 | 王钰滢（容器化） | registry 地址与凭据，或改走服务器上 `git pull` + `docker compose build` 的路径 |
| 4 | 部署作业 | 张嘉雨（CI/CD） | 在 main 触发、成功后输出可访问 URL 的 deploy job |

第 3 项有不依赖 registry 的替代路径：把 `deploy/` 拷到服务器直接构建。代价是构建耗时占服务器，且镜像 tag 与 commit 的对应要靠人工核对，E-04 的判定会退化为「人工记录」。
