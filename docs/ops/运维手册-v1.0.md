# CampusOverflow 运维手册 v1.0

> 适用环境：课程测试服务器（校园网内访问）。本手册以主干 `deploy/docker-compose.yml` 最终编排为准；命令、服务名、端口与仓库配置一一对应。
> 维护人：李增艳（SM）。上线前对照 `docs/ops/上线验收清单.md` 逐项核对。

## 1. 系统概述

### 1.1 服务组成

| 服务 | 容器名 | 镜像 / 构建 | 作用 | 端口 | 依赖 |
| --- | --- | --- | --- | --- | --- |
| MySQL | `co-mysql` | `mysql:8.0.39` | 业务数据（Flyway 管理表结构） | 3306 | — |
| Redis | `co-redis` | `redis:7-alpine` | 会话与列表缓存 | 6379 | — |
| 后端 | `co-backend` | `deploy/backend.Dockerfile`（多阶段构建） | Spring Boot 接口与业务逻辑 | 8080 | MySQL、Redis |
| 前端 | `co-web` | `deploy/frontend.Dockerfile` → nginx:alpine | 静态资源 + `/api` 反向代理 + SPA fallback | 80 | 后端 |
| Prometheus | `co-prometheus` | `prom/prometheus:v2.54.1`（observability profile） | 指标采集与告警评估 | 9090 | 后端指标端点 |
| Grafana | `co-grafana` | `grafana/grafana:11.2.0`（observability profile） | 指标面板 | 3000 | Prometheus |

### 1.2 仓库配置位置

- 编排文件：`deploy/docker-compose.yml`
- 后端镜像：`deploy/backend.Dockerfile`；前端镜像：`deploy/frontend.Dockerfile`；前端代理：`deploy/nginx.conf`
- 监控采集：`deploy/prometheus.yml`；告警规则：`deploy/prometheus/alerts.yml`
- Grafana 数据源与看板：`deploy/grafana/provisioning/`、`deploy/grafana/dashboards/campus-overflow.json`
- 后端指标端点：`/actuator/prometheus`；健康检查：`/actuator/health/readiness`

## 2. 环境变量与密钥

变量清单见 `deploy/.env.example`（随 PR #113 `feat/lab8-containerization` 合入主干；合入前在该分支查看）。复制为 `deploy/.env` 后按需修改，`deploy/.env` 已在 `.gitignore` 忽略、不入库。用法：`docker compose -f deploy/docker-compose.yml --env-file deploy/.env --profile observability up -d --build`。

### 2.1 必填项（无默认值，未设置直接退出）

| 变量 | 用途 | 说明 |
| --- | --- | --- |
| `CO_FIELD_KEY` | 字段加密密钥 | **必须自己生成，没有默认值**。compose 写法为 `${CO_FIELD_KEY:?CO_FIELD_KEY 未设置，见 deploy/.env.example}`，未设置会直接报错退出，避免带着示例密钥上线。本机生成（PowerShell）：`[Convert]::ToBase64String((1..32 \| ForEach-Object { Get-Random -Max 256 }))`；生产环境密钥必须与演示环境不同，经 `.env` 或 CI Secrets 注入，不得写进 Dockerfile / compose / 日志。 |

### 2.2 带默认值的变量（不建 `.env` 也能起，密钥项除外）

| `.env` 变量 | 用途 | 默认值 | 生产要求 |
| --- | --- | --- | --- |
| `MYSQL_ROOT_PASSWORD` | MySQL root 密码 | `root_dev_pwd` | 必须替换 |
| `DB_PASSWORD` | 业务库 `campus` 用户密码 | `campus_dev_pwd` | 必须替换 |
| `MYSQL_PORT` | 宿主机 MySQL 映射端口 | `3306` | 本机端口被占用时再改，不动 compose |
| `REDIS_PORT` | 宿主机 Redis 映射端口 | `6379` | 同上 |
| `BACKEND_PORT` | 宿主机后端映射端口 | `8080` | 同上 |
| `WEB_PORT` | 宿主机前端映射端口 | `80` | 同上 |
| `SPRING_PROFILES` | Spring profile（映射到容器内 `SPRING_PROFILES_ACTIVE`） | `prod` | 需要演示种子数据时显式写 `prod,demo`；正式环境只用 `prod` |
| `COOKIE_SECURE` | Cookie 仅在 HTTPS 下发送 | `false` | 经 HTTPS 发布时置 `true`；纯 HTTP 本地访问保持 `false`，否则登录态存不住 |
| `GRAFANA_PASSWORD` | Grafana 管理员密码 | `admin` | 必须替换 |

> 连接地址与账号 `DB_HOST=mysql`、`DB_USER=campus`、`REDIS_HOST=redis`、`TZ=UTC` 在 compose 内写死，容器网络内保持不变，不在 `.env.example` 中列出。
> 禁止在 Dockerfile、compose、日志中硬编码数据库密码与密钥；日志不得打印敏感信息。`.env` 不提交仓库。

## 3. 日常操作

> 以下命令在仓库根目录执行。

### 3.1 启动整套环境（含监控）

```bash
# 先复制 deploy/.env.example 为 deploy/.env 并填入 CO_FIELD_KEY（必填）
docker compose -f deploy/docker-compose.yml --env-file deploy/.env --profile observability up -d --build
```

仅启动业务服务（不含 Prometheus / Grafana）：

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d --build
```

> 未提供 `CO_FIELD_KEY` 时后端容器会按 `${CO_FIELD_KEY:?…}` 校验直接报错退出；其余变量缺省走默认值。首次启动等待健康检查通过：后端 `depends_on` 以 `service_healthy` 等待 MySQL、Redis；后端自身就绪探针为 `/actuator/health/readiness`。

### 3.2 查看状态与日志

```bash
# 服务状态
docker compose -f deploy/docker-compose.yml ps

# 跟随指定服务日志
docker compose -f deploy/docker-compose.yml logs -f <服务名>

# 实时资源占用
docker stats
```

常用服务名：`backend`、`web`、`mysql`、`redis`、`prometheus`、`grafana`。

### 3.3 停止与重启

```bash
# 停止整套环境（保留数据卷）
docker compose -f deploy/docker-compose.yml --profile observability stop

# 重启指定服务
docker compose -f deploy/docker-compose.yml restart <服务名>

# 代码更新后重新构建并启动
docker compose -f deploy/docker-compose.yml --profile observability up -d --build
```

### 3.4 健康验证

```bash
# 后端就绪探针（容器内 / 经 nginx 均可）
curl http://localhost:8080/actuator/health/readiness

# 指标端点（Prometheus 抓取来源）
curl http://localhost:8080/actuator/prometheus
```

前端通过 `http://<服务器地址>/` 访问；后端接口经 nginx `/api/` 代理到 `backend:8080`。

## 4. 发布与回滚

### 4.1 发布流程

1. 代码合并到 main，CI 完成编译、单测、架构约束、覆盖率与前端构建；
2. 镜像由 CI 镜像构建 Job 产出，部署 Job 通过 SSH 到测试服务器拉取镜像并 `up -d`；
3. 部署后自动调用 `/actuator/health` 做冒烟验证；
4. 人工核对前端域名可访问、Grafana 面板指标采集正常。

> 协作顺序：镜像构建与部署严格串行——Dockerfile / compose 先定稿且本地能启动，再接部署 Job；CI 配置文件由单人修改，避免两人同时改同一文件。

### 4.2 回滚步骤

| 步骤 | 操作 | 验证 |
| --- | --- | --- |
| 1 | 定位上一可用版本镜像标签（commit SHA / 版本标签） | 记录回滚目标版本 |
| 2 | 在部署配置中切回上一镜像标签 | 配置 diff 确认 |
| 3 | 拉取旧镜像并滚动重启 `docker compose pull && up -d` | 容器状态 healthy |
| 4 | 健康检查与冒烟：`/actuator/health/readiness` + 关键页面 + 核心指标 | 返回 UP、页面可用 |
| 5 | 记录回滚原因与版本到运维记录 / 缺陷清单 | 可追溯 |

> 若新版本含 Flyway 结构迁移，回滚前先确认旧版本与当前库结构兼容；不兼容时按数据备份流程恢复。

## 5. 常见故障处置

| 现象 | 可能原因 | 排查步骤 | 处置 / 回退 |
| --- | --- | --- | --- |
| 部署后访问 404 | nginx 与 SPA fallback 未配置；前端资源路径错误 | 查 `nginx.conf`、浏览器资源请求、容器内静态文件 | 修正 fallback 与 `try_files`，本地验证后再部署 |
| 后端健康检查失败 | MySQL / Redis 未就绪；环境变量缺失 | 看后端日志、依赖服务健康状态 | 等待健康检查通过；补环境变量；重启依赖服务 |
| 后端启动即退出（日志报 `CO_FIELD_KEY 未设置`） | 未注入字段加密密钥，compose `${CO_FIELD_KEY:?…}` 校验拦截 | 查后端容器日志与 `deploy/.env` | 按 2.1 生成并填入 `CO_FIELD_KEY`，重新 `up -d` |
| 接口 5xx 集中出现 | 下游依赖、空指针、数据不一致 | Grafana 5xx 曲线 + 后端错误日志 + 死信 / 对账指标 | 先回滚稳定版本，再按缺陷清单登记定位 |
| Grafana 无指标 | Prometheus 未抓到 `/actuator/prometheus`；指标名不匹配 | 查 Prometheus targets 状态与指标名 | 修正 scrape 配置与指标埋点 |
| 发件箱积压 / 死信上涨 | 消费者异常、事件重复投递 | 查 `co_outbox_backlog`、`co_outbox_dead_letters`、死信原因 | 按发件箱重试 / 死信流程处置，必要时人工补偿 |
| 声誉对账不一致 | 账本与账户余额偏差 | 查 `co_reputation_mismatches`、对账任务日志 | 触发对账 / 人工校正，登记缺陷 |
| 部署 Job 拉不到镜像 | 镜像未推送或标签不一致 | 查镜像仓库标签、部署 Job 变量 | 先完成镜像构建推送，再重试部署 |
