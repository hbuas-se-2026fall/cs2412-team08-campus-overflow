# Sprint 3 评审会主持稿（Lab6）

- 主持：李增艳（本轮过程负责人）
- 时间盒：每组 15～20 分钟，整场不超过 1 小时
- 现场要求：从 `main` 的版本标签启动演示，不演示分支上的半成品

## 一、会前十分钟检查清单

- [ ] `main` 最新提交的持续集成页面为绿（五个后端阶段 + 前端阶段）
- [ ] 版本标签已就位（v0.9.0），发布说明已写
- [ ] 演示用浏览器标签页按顺序排好：搜索页、问题详情、通知中心、声誉档案、排行榜
- [ ] 演示账号已准备：一个学生、一个教师、一个管理员
- [ ] 待演示的数据已存在：至少一条被采纳的问题、一条带悬赏的问题
- [ ] 投屏分辨率与字号检查（正文至少 14 号，评审后排能看清）
- [ ] 看板完成率、燃尽图截图已打开
- [ ] 记录人已安排（记录教师反馈与退回项）

## 二、主持流程与逐段话术

### 第 1 段 开场（1 分钟）

> 各位老师好，我们是第八组。本轮 Sprint 3 的目标是内容发现与端到端贯通：让用户能用中文关键词搜到问题、看到相关问题推荐、收到通知与 @ 提醒，同时移除行走骨架、让集成测试成为硬门禁，并给出候选版本 v0.9.0。
> 今天由我主持，先由产品负责人介绍目标与范围，再由开发同学现场演示，最后汇报质量与过程证据。

### 第 2 段 目标与范围（1 分钟，产品负责人）

要点：本轮纳入的必做项、明确不做的项、以及为什么。

### 第 3 段 现场演示（6～8 分钟）

按顺序走，每步一句话说明期望结果：

1. 打开首页，搜索中文关键词"跳表" → 命中相关问题列表；
2. 切到"红黑树" → 同样命中，说明分词与倒排索引生效；
3. 在搜索页按标签筛选、按"未回答"筛选、按悬赏筛选，切换四种排序 → 结果顺序变化；
4. 输入单字关键词 → 返回 422 与错误码 DIS-1001，说明入参校验生效；
5. 进入问题详情 → 右侧显示相关问题与相似度；
6. 删除一条问题后回到搜索 → 该问题不再出现（软删除与投影同步）；
7. 打开通知中心 → 未读数正确，单条已读、全部已读可用；
8. 在评论里 @ 一个昵称 → 对方收到通知，昵称高亮；
9. 打开声誉档案与排行榜 → 采纳带来的加分与徽章可见。

如果某项尚未完成，如实说明："这一项本轮未交付，原因是……，已纳入下一个 Sprint 的待办"，不要跳过或临时用分支代码顶替。

### 第 4 段 质量证据（2 分钟）

> 质量方面看三块：持续集成、覆盖率、端到端测试。
> 持续集成五个后端阶段加前端阶段全绿，链接在这里；
> 领域覆盖率本轮目标是 0.70，当前数据是……；
> 端到端测试 `CampusOverflowFlowIT` 覆盖了"提问→回答→采纳→声誉变化→搜索→通知"整条链路。
> 下面演示一次事件重放：把发件箱里一条已投递事件的投递时间置空，让它重新投递，声誉与徽章不重复变化。

重放演示是本次评审的加分项，务必提前演练一次。

### 第 5 段 过程证据（2 分钟）

- 燃尽图：说明中段是否有堆积、原因是什么；
- 速度变化：与上一个 Sprint 对比；
- 一次典型拉取请求评审：展示评审意见与修改提交的对应关系；
- 回顾会改进项的落实：上轮定的改进项现在是什么状态。

### 第 6 段 收尾与反馈（1 分钟）

> 以上是本轮增量。请老师指出需要退回或补做的项，我们记录后纳入下一个 Sprint 的待办列表。
> 会后我们立即开回顾会，用"开始—停止—继续"模板产出改进项并建 Issue 跟踪。

## 三、教师可能追问的问题与应答口径

| 提问 | 应答要点 |
|---|---|
| 为什么没有 `develop` 分支 | 如实说明本组以 `main` 为主干、功能分支直接提拉取请求的现状与原因，并说明已识别该偏差、后续如何纠正 |
| 声誉模块为什么还有骨架方法 | 承认未清零，说明实现所在分支与合入计划、责任人、截止时间 |
| 覆盖率为什么没到 0.70 | 给出当前数值与差距，说明补齐计划，不要用"测试不好写"作理由 |
| 事件重复投递会不会重复计分 | 说明发件箱至少一次投递、账本唯一键与已处理事件登记表，并现场重放验证 |
| 删除的内容为什么搜不到 | 说明软删除 + 投影标记删除，删除事件驱动搜索索引同步 |
