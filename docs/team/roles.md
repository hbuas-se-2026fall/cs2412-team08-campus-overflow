## 三、职责边界

### 3.1 三类角色各自的"唯一负责"

**PO（邹园园）**

- Product Backlog 的**唯一负责人**：条目增删、优先级排序、验收标准判定；
- 主持 Sprint Review，决定迭代成果是否被接受；
- **不兼任 SM**——既当裁判又当运动员会让"范围膨胀"失去制衡；
- 不直接给 Developer 分活，通过 Backlog 优先级表达意图。

**SM（李增艳）**

- 流程守护者：主持每日站会、Sprint Planning、Review、Retro；
- 维护看板与 CI 状态，按 §4 规则执行 Squash and merge；
- 主动识别并移除阻塞（环境、权限、依赖）；
- **不裁决技术细节**，不重分配"谁写哪段代码"，只保障流程被遵守。

**Developer（秦悦 / 张嘉雨 / 王钰滢）**

- 按 Issue 领取任务，负责实现、自测、补测试、提 PR；
- 评审他人 PR（作者不能批准自己的 PR）；
- 保障 DoD 达成——不是"写完"，而是"Definition of Done 全绿"；
- Lab 6、Lab 7 期间三人**轮值 QA**，当期 QA 对本轮交付质量负责。

### 3.2 决策权矩阵

| 事项 | 最终决策 | 需咨询 | 备注 |
| --- | --- | --- | --- |
| Backlog 条目优先级 | PO | 全员（估算输入） | PO 决策前须听 Developer 的成本意见 |
| 验收标准是否达成 | PO | 当期 QA | 有争议写进 Issue，不在群里口头结案 |
| Sprint 承诺范围 | 全员共识 | PO 提议 | 承诺是团队的承诺，不是 PO 派的包 |
| 分支合并节奏 / Squash | SM | — | 作者不得自行合并自己的 PR |
| 代码实现方案与选型 | 负责该模块的 Developer | 涉及接口变更时通知全员 | 变更已在 ADR 记录的须走 ADR 修订 |
| PR Approve | 至少 1 名非作者成员 | — | 章程 §5 |
| 每日站会 / 回顾主持 | SM | — | 轮换时交接待办清单 |
| Retro 改进措施取舍 | 全员投票 | SM 整理 | 平票时由 SM 加一票决定，并记录理由 |
| 分工与免责调整 | PO + SM 协商一致 | 相关成员 | 单方面不得调整他人任务 |

## 四、轮换机制

1. **SM**：每个 Sprint 末尾回顾会上投票决定是否轮换，得票过半即轮换；现任 SM 若连任，需在 Retro 记录中说明理由。
2. **QA**：Lab 6、Lab 7 由三名 Developer 轮值，每人至少担任一次，排期表见 `docs/lab1/提交物自检清单.md` 第六节。
3. **轮换必须走 PR**：任何角色变更都要修改本文件并提 PR，同时在站会同步。**禁止口头轮换**——课程成绩追溯看的是仓库记录，口头轮换在追溯时会断裂。
4. 轮换后原任需交接：进展中的 Issue、未关闭的评审、阻塞项清单。
