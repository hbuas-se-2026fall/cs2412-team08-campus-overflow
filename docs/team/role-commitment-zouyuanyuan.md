# PO 角色承诺书

> 对应课程手册 2.3.3《PO 角色承诺书》，与纸质签字版内容一致。

我，**邹园园**（签名），自愿担任 **计科2412班第5组** 组内的 PO（Product Owner，产品负责人）。
在本学期 4 个 Sprint 中承担如下职责：

1. 维护 Product Backlog：按价值与成本排定优先级，保证条目始终"就绪可执行"；
2. 每条 Story 写清验收标准（Gherkin Given / When / Then），开发开工前可验证、可判定；
3. 定义每个 Sprint 的目标与 MVP 范围，不被范围蔓延拖垮；
4. 在 Sprint Planning 讲解需求、在 Sprint Review 演示成果并把反馈转成 Backlog 条目；
5. 对需求疑问 24 小时内答复，不成为团队的阻塞点；
6. 尊重团队产能估算，不以行政压力逼承诺；对外部需求变更先与 SM、Dev 协商再决策。

我承诺每个 Sprint 至少贡献 **3 个 Story Point** 工作量（需求梳理、验收标准、文档类条目）。
若实际产能下降将主动告知 SM，共同调整 Backlog。

## 补充约定（与《团队章程 v1.0》联动，非手册模板内容）

为让上述职责可执行、可检查，补充以下量化约定：

| 职责条目 | 团队内的执行口径 |
| --- | --- |
| 第 1 条 Backlog | 见 `docs/backlog/ProductBacklog.md`；每条含 ID / 描述 / 优先级 / Story Point 四列，P0–P2 分级 |
| 第 2 条验收标准 | 对齐 Lab2 口径：每条 Story 配正常 / 边界 / 异常 3 个场景，Given-When-Then 三要素齐全，存放于 `docs/backlog/stories/US-XXX.feature` |
| 第 3 条 Sprint 目标 | 每个 Sprint 目标写成一句话，写进 Sprint 计划文档；中途加需求须走"换出等量 SP"的对等交换 |
| 第 4 条会议 | Planning 前完成条目讲解；Review 上演示可运行成果，收集到的反馈当天落成 Backlog 条目或 Issue |
| 第 5 条响应 | 飞书 / GitHub Issue 中的需求疑问，24 小时内给出答复或明确答复时间 |
| 第 6 条产能 | 尊重 `docs/backlog/sprint1-plan.md` 中的 Velocity 推导结果，承诺量不超过团队实际产能 |
