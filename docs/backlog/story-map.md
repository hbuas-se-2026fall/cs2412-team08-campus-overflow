## 读法

- **横轴（Backbone）**：用户从左到右的活动顺序，即一个人使用 CampusOverflow 的完整旅程；
- **纵轴（Walking Skeleton → Body）**：同一活动内，越靠上价值越高、越早交付；
- **切片线**：横线划过的是"某个版本最少要交付什么"；
- 优先级：**M** = Must，**S** = Should，**C** = Could。

## 三、Walking Skeleton（最小可演示链路）

```
PB-06 注册/登录/加入课程
        │
        ▼
PB-10 发布问题 ──→ PB-11 浏览列表
                          │
                          ▼
                    PB-12 查看详情
                          │
                          ▼
                    PB-13 提交回答
```

**为什么切这5条**：这是新用户从"打开平台"到"完成一次问答"的最短链路——

- **PB-06**：没有账号，后面所有写操作都没法做；
- **PB-10**：平台核心是提问，问题发不出来一切免谈；
- **PB-11**：问题发完必须能被列表看到，否则发完就消失；
- **PB-12**：用户要能点进详情页看问题描述和已有回答；
- **PB-13**：问了要有人答，演示才不断链（否则停在"已发布"）。

**合计 19 SP**（3+5+3+5+3）。砍掉任何一个环节演示都会断。

> 具体哪些故事进 Sprint 1、哪些延后，由 PO 在 Sprint Planning 上按 Velocity 决定；本图只标最小链路，不锁定 Sprint 范围。
