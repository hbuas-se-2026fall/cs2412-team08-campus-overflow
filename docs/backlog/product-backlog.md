# Product Backlog

## 一、这 35 条故事是从哪些"总的东西"拆出来的

**总的来源**：Lab2 第一步产出的**用户故事地图**。地图横轴是用户使用 CampusOverflow 的完整旅程——**注册 → 浏览 → 提问 → 回答 → 互动 → 成长 → 收尾**，横轴上的每一个**大活动**就是一个**史诗（Epic）**，比如"注册""发表问题""回答问题""获得声誉"。史诗太大，一个 Sprint 做不完也没法验收，所以再按"**一个角色 + 一条业务规则 + 一个可验收结果**"往下切，切出来的最小单元就是本表的 35 条 `PB-xx` 用户故事。

| 史诗（故事地图上的大活动） | 它拆出了哪些故事 | 拆分依据 |
|---|---|---|
| 注册与身份治理 | PB-06 ~ PB-09 | 按身份生命周期切：注册加入课程 → 维护资料 → 管理员认证与建账号 → 违规禁用 |
| 发表问题 | PB-10 | 单条，含标题/正文/标签/课程四类校验规则 |
| 浏览与发现内容 | PB-11、PB-12、PB-26、PB-27、PB-28 | 按找内容的方式切：列表筛选 → 看详情 → 搜索排序 → 索引同步 → 相关推荐 |
| 回答问题 | PB-13 | 单条，含未删除校验与正文长度规则 |
| 评价与互动 | PB-14、PB-15、PB-16、PB-17 | 按互动动作切：采纳最佳答案 → 投票 → 编辑/删除/教师认证 → 评论 |
| 声誉成长 | PB-19 ~ PB-23 | 按积分流向切：开户 → 采纳得分 → 投票得分 → 里程碑徽章 → 档案与排行榜 |
| 悬赏激励 | PB-24、PB-25 | 按资金流转切：发起并冻结积分 → 赢得或到期退回 |
| 消息通知 | PB-29、PB-30 | 按收发两侧切：五类事件触发 → 列表、已读与 @ 提醒 |
| 前端交互体验 | PB-31 ~ PB-33 | 按体验场景切：页内操作与中文报错 → 悬赏弹窗与声誉主页 → 加载与实时反馈 |
| 团队协作与工程基座 | PB-01 ~ PB-05 | 使能类，按交付链路切：仓库与分支保护 → 一键环境 → 统一语言 → CI 门禁 → 行走骨架建与拆 |
| 跨切面支撑 | PB-18 | 事件负载补全，为悬赏与通知提供上下文，不单独立项 |
| 质量保障与发布交付 | PB-34、PB-35 | 按验收环节切：测试补齐 → 监控、部署与 demo 数据 |

**一句话**：上表 12 个"总的东西"（史诗）→ 本表 35 条用户故事。切的时候不按技术分层切（不做"后端一条、前端一条、数据库一条"），而是切成能独立演示、独立验收的**垂直切片**——所以每条 `PB-xx` 都自带角色、规则和边界值。
