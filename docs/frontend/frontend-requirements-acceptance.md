# CampusOverflow 前端需求与页面验收标准

> 用途：定义前端页面交互需求与可验证的验收标准（Given/When/Then），供开发（张嘉雨、王钰滢）实现与联调后按此验收

---

## 1. 概述

### 1.1 实验目标

1. 搭建 React 18 + TypeScript 5 + Vite 工程，启用严格类型模式（strict + noUncheckedIndexedAccess）；
2. 配置 ESLint + Prettier + Husky pre-commit 钩子；
3. 完成路由、状态管理、API 客户端、组件库（Ant Design 5）的基础设施搭建；
4. 完成与后端的首个端到端贯通：**在前端发起提问并显示**。

### 1.2 提交物

1. 前端工程 `pnpm dev` 可启动，首页可访问；
2. `pnpm lint` 与 `pnpm typecheck` 全绿；
3. pre-commit 钩子可拦截不合规提交；
4. 提问 → 列表显示 → 详情查看 端到端跑通，录屏 30 秒以内。

### 1.3 本页面对应的用户故事

| PBI | 用户故事 | 优先级 |
| --- | --- | --- |
| PB-06 | 作为学生，我可以发布带标签、可关联课程的问题，以便向同学和老师求助 | Must |
| PB-07 | 作为用户，我可以分页浏览（按课程筛选）问题列表，以便发现待解决的问题 | Must |
| PB-08 | 作为用户，我可以查看问题详情（渲染后的正文、回答、评论、我的投票、可用操作） | Must |
| PB-19 | 作为用户，我可以在前端编辑/删除内容、发表评论与回复，并看到友好的错误提示 | Should |

## 3. 页面交互需求

### 3.1 P1 AppShell（全站布局）

**布局**：Header（顶部：Logo、主导航、登录用户信息/登录按钮）+ Sidebar（侧栏：问题、排行榜、通知入口）+ Outlet（内容区）。

| 需求编号 | 交互需求 | 说明 |
| --- | --- | --- |
| P1-1 | 未登录访客可浏览问题列表与详情，但提问/回答/投票/评论等写操作需跳转登录 | 访客角色（指导书 5.1） |
| P1-2 | 登录态显示当前用户昵称（displayName），提供退出入口 | 统一语言：displayName 对外展示 |
| P1-3 | 侧栏高亮当前路由对应入口 | 路由：/questions、/leaderboard、/notifications |
| P1-4 | 全局请求失败时展示统一错误提示（不白屏） | ErrorBoundary + QueryClient 全局配置 |

### 3.2 P2 提问页（/questions/new）

**表单字段**（对齐统一语言与领域规则）：

| 字段 | 控件 | 必填 | 规则 | 错误码 |
| --- | --- | --- | --- | --- |
| 标题 title | Input | 是 | 10–150 字符，去除首尾空白后校验 | QA-1001 |
| 标签 tags | Select multiple | 是 | 1–5 个，统一小写，支持中文与 `# + . - _`，去重 | QA-1005 |
| 课程 course | Select | 否 | 可选，选择当前用户已加入的课程 | — |
| 正文 markdownBody | TextArea | 是 | 20–30000 字符 | QA-1002 |

**交互流程**：
1. 填写表单 → 前端即时校验（长度/必填，与后端错误码文案一致）；
2. 提交 → `POST /api/v1/questions`，loading 态禁用提交按钮；
3. 成功 → 跳转详情页 `/questions/{id}` 并显示成功提示；
4. 失败 → 按后端错误码展示友好提示（见 4.3），不清空已填内容。

### 3.3 P3 问题列表页（/questions）

**页面元素**：课程筛选下拉 + 问题卡片列表 + 分页。

| 需求编号 | 交互需求 |
| --- | --- |
| P3-1 | 卡片显示：标题、标签、课程名、回答数、得分、作者昵称、创建时间（相对时间） |
| P3-2 | 支持按课程筛选（`courseId` 参数） |
| P3-3 | 支持分页浏览（`page`/`size`），页码切换重新请求 |
| P3-4 | 点击卡片跳转详情页 `/questions/{id}` |
| P3-5 | 空列表显示空态提示；加载中显示骨架屏；失败显示错误与重试按钮 |

### 3.4 P4 问题详情页（/questions/:id）

**页面元素**：问题标题/正文/标签 + 投票区 + 回答区 + 评论区 + 可用操作按钮。

| 需求编号 | 交互需求 |
| --- | --- |
| P4-1 | 正文按 Markdown 渲染且经净化（不渲染 XSS 脚本） |
| P4-2 | 显示标签、作者、创建时间、得分、回答数、是否已采纳（accepted 标记） |
| P4-3 | 投票：对问题/回答 +1 / −1，显示当前分数；**不能给自己的内容投票**（422 QA-1015） |
| P4-4 | 回答列表：Markdown 渲染、得分、采纳标记、教师认证标记 |
| P4-5 | 回答：仅未删除的问题可提交回答（QA-1020 已删除不可作答）；回答后列表刷新 |
| P4-6 | 评论与回复：可对问题/回答评论（2–600 字符 QA-1003），回复仅允许一层（QA-1016） |
| P4-7 | 可用操作按 permissions 显示：提问者/课程管理者显示编辑、删除；教师/助教显示采纳、教师认证 |
| P4-8 | 错误提示友好：权限错误 403、冲突 409、校验 422 均转换为可读文案 |

### 4.2 功能验收（端到端：提问 → 列表 → 详情）

| # | Given | When | Then |
| --- | --- | --- | --- |
| F1 | 学生已登录 | 在提问页填写合法问题（标题 ≥10 字、1–5 个标签、正文 ≥20 字）并提交 | 创建成功；跳转详情页；正文正确渲染 |
| F2 | 已发布若干问题 | 访问 `/questions` 列表页 | 新发布的问题出现在列表第一条，显示标题/标签/回答数 |
| F3 | 列表页存在某问题 | 点击该问题卡片 | 进入详情页，正文/标签/作者/时间完整显示 |
| F4 | 问题详情页打开 | 输入合法评论（2–600 字）并提交 | 评论出现在评论区，无需刷新 |
| F5 | 详情页打开 | 提交一个标题不足 10 字的问题（提问页） | 前端即时提示标题长度规则（QA-1001），请求未发出 |
| F6 | 演示全程 | 完成"提问 → 列表显示 → 详情查看" | 录屏 ≤ 30 秒，端到端链路真实跑通 |

### 4.3 错误场景验收（友好提示）

| # | Given | When | Then | 期望提示 |
| --- | --- | --- | --- | --- |
| A1 | 未登录 | 点击提问/回答/投票/评论 | 跳转登录页或提示先登录 | 登录引导 |
| A2 | 提问页 | 提交标题 9 字问题 | 提示 QA-1001 | "标题需 10–150 个字符" |
| A3 | 提问页 | 提交正文少于 20 字 | 提示 QA-1002 | "正文需 20–30000 个字符" |
| A4 | 详情页 | 评论少于 2 字 | 提示 QA-1003 | "评论需 2–600 个字符" |
| A5 | 详情页 | 对自己的问题/回答投票 | 后端 422 QA-1015，前端提示 | "不能给自己的内容投票" |
| A6 | 详情页 | 普通学生点击采纳 | 后端 403 QA-3001，前端提示 | "只有提问者或课程教师/助教可以采纳" |
| A7 | 详情页 | 非作者点击编辑 | 按钮不显示（permissions 控制） | 不出现编辑入口 |
| A8 | 详情页 | 问题已删除/回答已删除仍操作 | 后端 409 QA-1020，前端提示 | "内容已删除" |

> 验收口径：错误提示文案与 `docs/错误码.md` 一致；网络错误（5xx/超时）显示"服务暂不可用，请稍后重试"并提供重试按钮。

## 5. 页面原型逻辑审核

### 5.1 原型逻辑说明（开发实现的基准）

```
AppShell（Header + Sidebar + Outlet）
├── Header：Logo | 主导航（问题 / 排行榜 / 通知）| 用户区（昵称 + 退出 | 登录按钮）
├── Sidebar：当前路由高亮（/questions、/leaderboard、/notifications）
└── Outlet
    ├── /questions            → 问题列表页（课程筛选 + 卡片列表 + 分页）
    ├── /questions/new        → 提问页（标题 + 标签 + 课程 + 正文 + 提交）
    └── /questions/:id        → 详情页（正文渲染 + 投票 + 回答 + 评论 + 可用操作）
```

**关键逻辑约束**：
1. 写操作权限由后端强制校验，前端仅按返回的 permissions 隐藏按钮（不做安全边界）；
2. 服务器状态用 TanStack Query 缓存，客户端状态（表单、筛选、分页）用 Zustand，禁止 prop drilling；
3. 所有接口错误统一经 axios 拦截器解析 `{code, message}` 后映射为友好文案。

### 5.2 审核结论

| 审核项 | 结论 |
| --- | --- |
| 页面覆盖完整（提问/列表/详情/AppShell） | 通过：覆盖详案提交物 4 的端到端路径 |
| 字段规则与领域层一致（10–150 / 1–5 / 20–30000 / 2–600） | 通过：与 QA-1001~1006 及术语表一致 |
| 权限模型正确（课程管理者/教师/助教/作者） | 通过：对齐统一语言与错误码 QA-3001~3004 |
| 错误提示覆盖关键失败场景 | 通过：见 4.3，含权限/校验/冲突/网络四类 |
| 统一语言使用 | 通过：页面文案使用 title/tags/answer/comment/accept 等规范术语 |

## 6. 端到端验收流程（录屏脚本，≤ 30 秒）

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| 1 | `pnpm dev` 启动前端，打开首页 | 列表页加载，展示已有问题 |
| 2 | 登录（或使用已登录会话） | Header 显示昵称 |
| 3 | 进入 `/questions/new`，填写合法问题并提交 | 跳转详情页，正文渲染 |
| 4 | 返回 `/questions` | 新问题出现在列表 |
| 5 | 点击该问题 | 详情页完整显示（标题/标签/正文/回答数） |
