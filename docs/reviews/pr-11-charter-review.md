## 四、评审意见

### must（未解决不合入）

**M1 · 文件名少一个 `.0`**
手册 Lab 1 Step 4 原文：`提交至 docs/team/charter-v1.0.md`。Lab 1 提交物 3 就是这份文件，名字对不上会直接影响核对。
```bash
git mv docs/team/charter-v1.md docs/team/charter-v1.0.md
git commit -m "docs(team): 章程文件名对齐手册要求 charter-v1.0.md　签署：秦悦"
git push origin feat/add-team-charter-v1.0-1
```

**M2 · commit message 没有签名**
手册同一步原文：`由全员签字（commit message 包含签名）`。当前 commit 无签名。建议作者在新 commit 末尾加 `签署：秦悦`；其余 4 人在 PR 里各留一条「已阅并同意，签署：XXX」评论作为签署凭证——比在表格里替全员代签更站得住脚（见 S1）。

**M3 · 沟通渠道写 QQ 群，实际是微信群**
§3.1 第 64 行写「团队 QQ群」，而我们实际建的是**微信群**；手册 Step 2 列的也是 微信/飞书/Discord。Lab 1 评分「工具链完整性 30%」含 IM，教师核对时发现章程与实际不符会扣分。已挂 suggestion。

**M4 · 标题区有编辑残留**
第 3 行 `2026 年 __10 月 _27_ 日` 的下划线在 Markdown 里会渲染成斜体乱码；第 4 行孤立的 `27` 是残留。已挂 suggestion。

### suggest（作者须回复采纳与否）

**S1 · 签字栏不要替全员代签**（第 ~200 行）
§六 表格里 5 人的名字和日期 2026.10.27 都已填好，但这份 PR 尚未经全员 Approve/评论。建议在表格下加一句「本人签署以本 PR 的 Approve 或『已阅并同意』评论为准」，或先留白。

**S2 · 补 QA 与角色轮换**（§一）
手册第 9 行硬性要求「Developer（其中 1 名兼 QA）。角色每个 Sprint 末尾可投票轮换」。建议在成员表下补两句：某 Sprint 由哪名 Developer 兼 QA、以及轮换规则。我们分工表里 QA 是由秦悦 / 张嘉雨 / 王钰滢 在 Lab 6、Lab 7 轮值。

**S3 · 分支命名自己违反自己**（第 112 行 + 本 PR 分支名）
§4.1 规定 `feature/<姓名拼音>-<主题>`，但本 PR 分支是 `feat/add-team-charter-v1.0-1`——前缀 `feat/` 不是 `feature/`，且连字符混入了非 ASCII 字符（U+2011）。另外仓库里 `feature/LZY-hello` 用的是缩写不是全拼，我的 PR #2 从 10-24 开到现在也没合，「存活不超过 3 天」目前做不到。建议：本分支改名 `feature/qinyue-charter`；把「不超过 3 天」改成「尽量 3 天内合并，超期在站会说明」。

**S4 · §4.3「文件名只用英文或拼音」与仓库现状冲突**（第 132 行）
`docs/学生任务清单.md`、`docs/错误码.md` 是教师给的初始文件，本来就是中文名。建议加「教师提供的初始文件除外」。

**S5 · §5.1 未写由谁合并**（第 166 行）
团队既有约定：1 人 Approve → **SM 用 Squash and merge 合并，合并者不自行批准自己的 PR**。建议补进 DoD，把流程闭环写死。
