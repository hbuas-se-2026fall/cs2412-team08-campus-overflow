## 四、评审意见

### must（未解决不合入）

**M1 · 缩进被抹平，产生 108 行无关 diff**

原文件 `Scenario` 缩进 2 空格、`Given/When/Then` 缩进 4 空格，是标准的 Gherkin 层级写法。本次全部改为顶格：

```diff
-  Scenario: 正常注册账号
-    Given 用户是未注册的学生
-    When 用户填写合法账号信息，提交注册
-    Then 账号注册成功，可以登录平台
+Scenario: 正常注册账号
+Given 用户是未注册的学生
+When 用户填写合法账号信息，提交注册
+Then 账号注册成功，可以登录平台
+# 【快乐路径】
```

后果：9 个文件每一行都进了 diff，真正的新增内容（27 行标注）被淹没；同时王钰滢的 PR #24 也在改这批文件，缩进差异会让合并冲突更难处理。

**改法**：保留原缩进不动，只加 tag。如果已经用编辑器全局重排了，先 `git checkout cf0e602 -- docs/backlog/stories/` 恢复原文件，再重新只加 tag 提交一次，让 diff 干净。

**M2 · 用注释标注路径类型，工具读不到**

`# 【快乐路径】` 是注释，Gherkin 解析器直接忽略。Lab 2 评分里「可测试性」占 25%，验收标准应该能被自动化框架识别和筛选，注释做不到这一点。

**改法**：改用 Gherkin tag，写在 Scenario 行**上方**：

```gherkin
Feature: US-001 学生注册账号
  As a 未注册的学生
  I want 用学号邮箱注册账号
  So that 我能在平台上提问和回答

  @happy-path @SC-001
  Scenario: 正常注册账号
    Given 用户是未注册的学生
    When 用户填写合法账号信息，提交注册
    Then 账号注册成功，可以登录平台

  @boundary @SC-002
  Scenario: 边界场景-用户名超长
    Given 用户是未注册的学生
    When 用户填写超过长度限制的用户名，提交注册
    Then 系统提示用户名过长，注册失败

  @error-path @SC-003
  Scenario: 异常场景-重复用户名注册
    Given 平台已存在该用户名
    When 用户使用这个已存在的用户名提交注册
    Then 系统提示用户名已被占用，注册失败
```

这样 `cucumber --tags @happy-path` 能一键跑全部快乐路径，`@error-path` 跑全部异常路径——这才是「可测试」的验收标准。

### suggest（作者须回复采纳与否）

**S1 · tag 建议用英文**
`@happy-path` / `@boundary` / `@error-path`。中文 tag 虽然 Gherkin 允许，但部分工具链对非 ASCII tag 支持不佳，且与团队其余英文标识符（`US-001`、`SC-001`）混用不统一。

**S2 · 补 SC 编号**
每个场景加 `@SC-001` 形式的编号，方便后续 Lab 6/7 写测试用例时一一对应，评审时也更好指代「SC-003 这条有问题」而不是「第三个场景」。

**S3 · US-009 的「边界场景」其实不是边界**
`边界场景-清空原有内容，重新填写` → `Then 更新成功`。清空后重填合法内容是正常操作，结果也是成功，应归为 `@happy-path`。真正的边界应该是「标题只填 1 个字符」「内容达到上限 5000 字」这类。建议复核其余 8 个 feature 的边界场景是否也有同类问题。

**S4 · 9 个 Feature 头都缺 `As a / I want / So that`**
不是本 PR 引入的，但既然在改这批文件，顺手补上成本很低，且能直接提升 Lab 2 评分里的「用户故事质量」。如不愿扩大改动范围，可以另开一个 PR 处理，本 PR 只管 tag。
